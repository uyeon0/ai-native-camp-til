# 오늘의 한 줄 스펙

앱 이름은 "오늘의 한 줄"이다. 하루에 한 줄씩 회고를 남기고, 남긴 날을 GitHub 잔디처럼 연간 격자에 칠해 보여 준다. 서버 없이 브라우저에서만 동작한다.

## 목표

- 오늘의 회고를 한 줄로 빠르게 남긴다.
- 최근 1년 동안 회고를 쓴 날과 쓰지 않은 날을 한눈에 본다.
- 지난 날짜의 회고도 새로 쓰거나 고친다.

## 범위 밖

- 서버, 로그인, 기기 간 동기화
- 여러 줄 일기나 태그, 검색
- AI 기능 (서비스는 AI 없이 동작한다)
- 데이터 내보내기·가져오기
- 연속 작성 일수(streak) 표시
- 다크 모드
- 모바일 사용성. 이 버전은 컴퓨터 브라우저에서 쓰는 것을 기준으로 만든다. 모바일에서는 화면이 깨지지 않고 잔디를 옆으로 밀어 볼 수 있는 데까지만 지원한다. 모바일에는 hover가 없고, 칸을 누르면 입력창에 포커스가 가서 키보드가 올라오고, 칸이 손가락으로 누르기에 작다. 이 문제는 나중에 모바일을 따로 디벨롭할 때 다룬다.

## 기술 스택

빌드 도구 없이 Vanilla HTML, CSS, JavaScript로 만든다. 데이터는 `localStorage`에 저장한다. 외부 라이브러리는 쓰지 않는다.

## 디렉토리 구조

```
001-daily-retro/
├── docs/
│   └── spec.md
└── index.html
```

HTML, CSS, JavaScript를 모두 `index.html` 하나에 넣는다. `index.html`을 브라우저에서 바로 열어 실행한다. 스크립트는 `<script type="module">`이 아니라 일반 인라인 스크립트로 쓴다. 나중에 파일을 나눌 때 `file://`에서 모듈 스크립트가 CORS 제한에 걸리지 않게 하기 위해서다.

## 화면

한 화면에 입력 영역과 잔디 영역이 있다.

### 입력 영역

잔디 위에 있다. 선택된 날짜와 한 줄 입력창을 보여 준다. 처음 열면 오늘 날짜가 선택되어 있고, 그날 쓴 회고가 있으면 입력창에 채워져 있다. 페이지를 열면 입력창에 바로 포커스를 줘서 클릭하지 않고 쓸 수 있게 한다. 모바일 브라우저, 특히 iOS Safari는 사용자가 누르지 않은 포커스로는 키보드를 띄우지 않는다. 모바일에서는 입력창을 한 번 눌러야 쓸 수 있다. Enter를 누르거나 입력창 아래의 Enter 안내를 누르면 저장한다.

### 잔디 영역

입력 영역 아래에 있다. 잔디 위에 왼쪽에는 "지난 1년", 오른쪽에는 그 기간에 회고를 쓴 날 수("301일" 형식)를 작은 회색 글씨로 쓴다. 최근 1년을 주 단위 열, 요일 단위 행으로 나눈 격자를 그린다. 회고를 쓴 날의 칸은 칠하고, 쓰지 않은 날의 칸은 비워 둔다. 칸에 마우스를 올리면 잔디 아래에 날짜와 회고 내용을 보여 준다. 칸을 클릭하면 그 날짜가 선택되어 입력 영역에서 쓰거나 고칠 수 있다. 오늘 이후의 칸은 그리지 않는다.

## 잔디 격자

GitHub 기여 그래프와 같은 배치를 따른다.

- 열 하나가 한 주(일요일 시작)이고, 행 하나가 요일이다.
- 마지막 열은 오늘이 속한 주이고, 그 앞으로 52주를 더 그려 모두 53열이 된다.
- 첫 열의 일요일부터 오늘까지 날짜를 하루씩 늘리며 칸을 만든다.
- 열 위에 월 이름을, 행 왼쪽에 요일 이름(월, 수, 금)을 표시한다.

격자는 주 하나를 7행짜리 CSS Grid 열로 만들고, 열들을 flex로 가로로 늘어놓는다. 열을 따로 두는 이유는 달이 바뀌는 주에 여백을 넣기 위해서다. 한 달의 1일이 들어 있는 열에는 `margin-left: 3px`를 준다.

## 디자인

흰 바탕에 글자와 여백만 남긴 미니멀 디자인이다. 테두리, 그림자, 배경 무늬 같은 장식은 쓰지 않는다.

### 배치

가운데에 최대 너비 600px의 단 하나를 두고, 위에서부터 날짜, 입력창, 잔디를 한 덩어리로 쌓는다. 잔디는 입력창 아래 72px(화면 너비 520px 이하에서는 56px) 간격에 둔다. 덩어리 전체는 화면 세로 가운데보다 살짝 위에 놓는다. 아래 여백을 위 여백보다 크게 주면 눈으로 볼 때 가운데에 있는 것처럼 보인다.

입력창과 잔디 사이를 화면 끝까지 벌리지 않는다. 회고가 한 줄뿐이라 그 사이가 늘 비어 보이기 때문이다.

### 색과 글꼴

| 용도 | 색 |
|---|---|
| 배경 | `#FFFFFF` |
| 본문 글자 | `#2B2B2B` |
| 날짜, 안내 문구 | `#A3A3A3` |
| 입력창 placeholder | `#D6D6D6` |

회고 본문과 입력창은 나눔명조, 날짜와 안내 문구는 Noto Sans KR 300으로 쓴다. 둘 다 Google Fonts에서 불러오고, 네트워크가 없을 때를 위해 시스템 명조와 산세리프 글꼴을 대체 글꼴로 지정한다.

### 날짜와 입력창

날짜는 "2026년 10월 14일 수요일" 형식으로 작은 회색 글씨로 쓴다. 지난 날짜를 선택했을 때는 날짜 옆에 "오늘로" 버튼을 보여 준다.

입력창은 테두리와 밑줄 없이 placeholder만 보인다. placeholder는 오늘이면 "오늘을 한 줄로", 지난 날짜면 "이날을 한 줄로"다. 글자 크기는 22px다. Enter로 저장하고, 모바일 키보드의 Enter 키에 "완료"가 표시되도록 `enterkeyhint="done"`을 준다.

입력창에 포커스가 있거나 입력창 내용이 저장된 내용과 다르면, 오른쪽 아래 글자 수 바로 아래에 Enter 안내를 글자 수와 같은 회색(`#A3A3A3`)으로 보여 준다. 안내를 클릭해도 Enter와 똑같이 동작한다. 안내 문구와 저장 뒤 결과 문구는 상황에 따라 다르다.

| 상황 | 안내 | 결과 |
|---|---|---|
| 회고가 없는 날에 새로 씀 | Enter를 눌러 저장 | 저장했어요 |
| 이미 쓴 회고를 고침 | Enter를 눌러 수정 | 수정했어요 |
| 이미 쓴 회고를 모두 지움 | Enter를 눌러 삭제 | 삭제했어요 |

터치 기기(`pointer: coarse`)에서는 "Enter" 대신 "완료"로 보여 준다. 안내 자리는 처음부터 비워 두고 `visibility: hidden`으로 숨겨서, 나타날 때 아래 잔디가 밀리지 않게 한다.

Enter를 누르면 결과 문구가 안내가 있던 자리에 본문 글자색으로 1.8초 동안 보였다가 서서히 사라진다. 사용자가 방금 본 안내 자리에 결과를 보여 줘야 저장된 걸 알아챈다. 내용이 바뀌지 않았으면 Enter를 눌러도 아무 일도 일어나지 않는다.

회고는 최대 140자다. 트위터가 한국어에 두고 있는 제한과 같다. 140자는 화면에서 여러 줄이 되므로 입력창은 `<textarea>`로 만들고, 글이 길어지면 높이가 따라 늘어난다. 줄바꿈은 받지 않는다. 붙여넣은 글의 줄바꿈은 공백으로 바꾼다.

한글을 조합하는 중에 Enter를 눌러도 한 번에 저장되어야 한다. 브라우저마다 이벤트 순서가 다르다고 알려져 있다. macOS Chrome은 조합 중 `keydown`(`isComposing: true`)과 조합이 끝난 뒤 `keydown`을 한 번 더 보내고, Safari는 `compositionend` 뒤에 `keyCode` `229`인 `keydown`을 보낸다. 실제 Safari에서는 아직 확인하지 않았다. 그래서 Enter의 `keydown`은 항상 기본 동작을 막고, `isComposing`이 `true`면 저장을 미뤄 두었다가 `compositionend`에서 저장한다. `isComposing`이 `false`면 바로 저장한다. 저장은 입력창 내용이 저장된 내용과 같으면 아무것도 하지 않으므로, 두 번 불려도 결과가 같다.

입력창 오른쪽 아래에 "23 / 140" 형식으로 글자 수를 보여 준다. 입력창에 포커스가 있을 때만 보이고, 120자 이상이면 포커스와 상관없이 본문 글자색으로 진하게 보인다. 글자 수 제한은 `maxlength="140"`으로 건다. `maxlength`는 UTF-16 코드 단위로 세므로 이모지 하나가 2자로 셀 수 있다.

### 잔디 칸

칸은 8px 정사각형이고 모서리를 2px 둥글린다. 칸 사이 간격은 2px다. 이 크기면 53주와 달 사이 여백을 합쳐 약 564px라 600px 단 안에 1년이 스크롤 없이 들어간다.

화면 너비가 640px 이하면 1년이 다 들어가지 않으므로 칸을 10px, 간격을 3px, 모서리를 2.5px로 키우고 잔디를 가로 스크롤로 보여 준다. 처음에는 오른쪽 끝(오늘)이 보이게 스크롤해 둔다. 스크롤바는 숨기고, 왼쪽에 칸이 더 있으면 잔디 왼쪽 끝 40px를 `mask-image`로 흐리게 해서 밀어 볼 수 있다는 걸 보여 준다. 쓰지 않은 날의 칸은 `#F0F0EE`로 칠한다. 쓴 날의 칸은 그 날짜가 속한 달의 파스텔 색으로 칠하고, 색은 한 단계만 쓴다.

| 월 | 색 | 월 | 색 | 월 | 색 |
|---|---|---|---|---|---|
| 1월 | `#A9B4CC` | 5월 | `#B7CDB4` | 9월 | `#DCCA9F` |
| 2월 | `#B6ACC8` | 6월 | `#A8C8C2` | 10월 | `#D8B198` |
| 3월 | `#C9B9D0` | 7월 | `#A3C3CE` | 11월 | `#C6AB9E` |
| 4월 | `#E5B9C1` | 8월 | `#AEC4D9` | 12월 | `#AAB4BC` |

쓴 날의 칸은 기울기를 -1°, 0°, 1° 중 하나로, 불투명도를 0.90~1.00 사이로 조금씩 다르게 준다. 이 값은 날짜 문자열의 해시로 정하므로 새로고침해도 바뀌지 않는다.

아직 쓰지 않은 오늘 칸은 1px 회색 테두리로 자리만 표시한다. 선택된 지난 날짜의 칸에는 1px 글자색 외곽선을 그린다. 회고를 저장하면 칸 색이 0.7초 동안 서서히 나타난다. `prefers-reduced-motion`이 켜져 있으면 애니메이션 없이 바로 칠한다.

칸에 마우스를 올리면 잔디 바로 아래에 날짜와 회고를 글씨로 보여 준다. 툴팁 상자는 쓰지 않는다.

## 데이터

`localStorage`의 키 하나에 모든 회고를 JSON으로 저장한다.

- 키: `daily-retro:v1`
- 값: 날짜 문자열을 키로 하는 객체

```json
{
  "2026-10-14": { "text": "스펙 문서를 썼다", "updatedAt": "2026-10-14T16:10:00+09:00" }
}
```

날짜 키는 사용자의 **로컬 날짜**로 만든다. `new Date().toISOString().slice(0, 10)`은 UTC 기준이라 한국 시간 오전 9시 전에는 전날 날짜가 나온다. `getFullYear()`, `getMonth()`, `getDate()`로 `YYYY-MM-DD`를 직접 조립한다.

빈 문자열을 저장하면 그날의 항목을 지운다. 이렇게 하면 따로 삭제 버튼을 두지 않고 회고를 지울 수 있다.

키에 붙인 `v1`은 나중에 데이터 형식을 바꿀 때 이전 데이터를 구분하려고 둔다.

## 동작 흐름

1. 페이지를 열면 `localStorage`에서 `daily-retro:v1`을 읽는다. 값이 없거나 JSON 파싱에 실패하면 빈 객체로 시작한다.
2. 오늘 날짜를 선택하고 입력 영역과 잔디 영역을 그린다.
3. 사용자가 저장하면 객체를 고치고 `localStorage`에 다시 쓴 뒤, 해당 칸만 다시 칠한다.
4. 사용자가 칸을 클릭하면 선택된 날짜를 바꾸고 입력창에 그날의 내용을 채운다.

`localStorage`에 쓰지 못하면(저장 공간이 꽉 찼거나 브라우저가 막은 경우) 메모리의 상태도 되돌리고 결과 문구 자리에 "저장하지 못했어요"를 보여 준다.

페이지를 켜 둔 채 자정이 지나면 오늘 날짜가 바뀐다. 탭으로 돌아오거나 창에 포커스가 올 때, 그리고 1분마다 날짜를 확인한다. 날짜가 바뀌었고 입력창에 저장하지 않은 내용이 없으면 새 날짜를 기준으로 잔디와 입력 영역을 다시 그린다. 저장하지 않은 내용이 있으면 그 내용을 지우지 않으려고 다시 그리지 않는다.
