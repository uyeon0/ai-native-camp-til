# 커밋 메시지 빌더 스펙

"커밋 메시지 빌더" 프로젝트다. type, scope, description, body, footer를 칸마다 입력하면 Conventional Commits 형식의 커밋 메시지로 조합해 보여 주고, 버튼 하나로 클립보드에 복사한다. 서버 없이 브라우저에서만 동작한다.

빌더는 사용자가 입력한 내용을 바꾸지 않는다. 괄호, 콜론, 빈 줄처럼 형식에 필요한 기호만 붙여서 이어 붙인다. 메시지 규칙은 kocommit 규칙에서 형식에 관한 것만 따른다.

## 목표

- 커밋 메시지를 형식을 신경 쓰지 않고 내용만 입력해서 만든다.
- 조합된 메시지를 입력하는 동안 바로 확인한다.
- 조합된 메시지를 버튼 하나로 복사한다.

## 범위 밖

- 문장 생성, 자동 교정 같은 내용 수정 (서비스는 AI 없이 동작한다)
- kocommit 규칙 중 내용에 관한 검사: 금지어, 줄 끝 마침표, `-다`·`-요` 종결어미, body bullet 형식
- 입력값 저장. 새로고침하면 모든 칸이 비워진다.
- `git diff` 읽기나 `git commit` 실행 같은 저장소 연동
- 모바일 사용성. 001과 마찬가지로 컴퓨터 브라우저를 기준으로 만든다.

## 기술 스택

빌드 도구 없이 Vanilla HTML, CSS, JavaScript로 만든다. 외부 라이브러리는 쓰지 않는다. 복사는 Clipboard API(`navigator.clipboard.writeText`)로 한다.

## 디렉토리 구조

```
002-commit-builder/
├── docs/
│   └── spec.md
└── index.html
```

HTML, CSS, JavaScript를 모두 `index.html` 하나에 넣고, 브라우저에서 바로 열어 실행한다. 001과 같은 이유로 스크립트는 `<script type="module">`이 아니라 일반 인라인 스크립트로 쓴다.

`navigator.clipboard`는 보안 컨텍스트에서만 쓸 수 있다. 크롬은 `file://`도 보안 컨텍스트로 취급한다고 알려져 있지만, 브라우저마다 다른지는 아직 확인하지 않았다.

## 화면

왼쪽에 입력 영역, 오른쪽에 미리보기 영역을 두는 두 단 배치다. 입력 칸을 고칠 때마다 미리보기가 바로 바뀐다.

### 입력 영역

위에서부터 아래 칸을 둔다.

| 칸 | 입력 방식 | 필수 | 주석 |
|---|---|---|---|
| type | 8개 중 하나를 고름 | 예 | 고른 type의 용도 |
| scope | 한 줄 텍스트 | 아니요 | 변경한 범위. 비우면 괄호 없이 조합 |
| description | 한 줄 텍스트 | 예 | 무엇을 바꿨는지 한 줄 요약 |
| body | 여러 줄 텍스트 | 아니요 | 바꾼 이유 등 추가 설명 |
| BREAKING CHANGE | 한 줄 텍스트 | 아니요 | 기존 사용 방식과 호환되지 않는 변경 설명 |
| Co-Authored-By | 이름과 이메일 칸 한 쌍, 여러 쌍 추가 가능 | 아니요 | 함께 작업한 사람. 이름과 이메일이 모두 있어야 조합 / GitHub 계정에 등록된 이메일을 써야 GitHub에 표시 |

필수인 칸은 칸 이름 옆에 "필수"를 적고, 필수가 아닌 칸에는 아무것도 적지 않는다. 칸마다 아래에 `// `로 시작하는 주석을 보조 글자로 보여 줘서, Conventional Commits를 모르는 사람도 칸에 무엇을 쓸지 알게 한다.

placeholder는 보조 글자색이라 입력한 값과 헷갈리지 않도록, 예시를 넣는 칸은 앞에 `예: `를 붙인다(예: `예: 002-commit-builder`). Co-Authored-By의 "이름", "이메일"은 예시가 아니라 칸 이름이므로 그대로 쓴다.

type은 kocommit이 허용하는 `feat`, `fix`, `docs`, `style`, `refactor`, `test`, `chore`, `revert` 8개이고, 고른 type의 용도를 칸 아래 주석으로 보여 준다.

| type | 용도 |
|---|---|
| `feat` | 새 기능 |
| `fix` | 버그 수정 |
| `docs` | 문서만 변경 |
| `style` | 동작이 바뀌지 않는 포맷팅 |
| `refactor` | 동작을 바꾸지 않는 구조 변경 |
| `test` | 테스트 추가·수정 |
| `chore` | 의존성, 도구 설정 등 유지보수 |
| `revert` | 이전 커밋 되돌리기 |

BREAKING CHANGE 칸은 주석 다음 줄에 "BREAKING CHANGE 커밋은 `type(scope)` 뒤에 `!` 추가"라는 안내를 같은 주석 모양으로 보여 준다. 입력값에 따라 바뀌지 않는 고정 문구이고, 위에 있는 type, scope 칸 이름으로 위치를 알려 준다. `!`가 왜 붙었는지 Conventional Commits를 모르는 사람도 알 수 있게 하기 위해서다.

Co-Authored-By는 처음에 이름·이메일 칸 한 쌍을 보여 준다. 한 쌍 안에서 이름 칸 아래에 이메일 칸을 두고, 쌍 아래 오른쪽 끝에 "삭제" 버튼을 둔다. 입력 칸은 다른 칸과 같은 너비로 두고, "삭제"는 "추가"와 같은 세로선에 맞춘다. "추가" 버튼은 Co-Authored-By 칸 이름의 오른쪽 끝에 두고, 누르면 목록 맨 아래에 쌍이 하나 늘어난다.

### 미리보기 영역

조합된 메시지를 고정폭 글꼴로 줄바꿈까지 그대로 보여 준다. 미리보기보다 긴 줄은 미리보기 안에서 줄바꿈해서, 가로 스크롤 없이 50자를 넘긴 부분까지 보이게 한다. 미리보기 아래 상태 줄에 title 글자 수와 복사 버튼을 둔다.

## 조합 규칙

조합된 메시지는 title, body, footer 순서이고, 각 부분 사이에 빈 줄을 하나 넣는다. 비어 있는 부분은 빼고, 그 앞뒤의 빈 줄도 넣지 않는다.

```
feat(002-commit-builder)!: 조합 규칙 변경

- 첫 번째 항목
- 두 번째 항목

BREAKING CHANGE: footer 순서 변경
Co-Authored-By: Kim <kim@example.com>
```

body를 뺀 각 칸은 앞뒤 공백을 지우고 조합한다.

### title

`<type>(<scope>)<!>: <description>` 형식으로 만든다.

- scope가 비어 있으면 괄호를 쓰지 않는다. 예: `feat: 조합 규칙 변경`
- BREAKING CHANGE 칸에 내용이 있을 때만 scope 뒤(scope가 없으면 type 뒤)에 `!`를 붙인다. Conventional Commits는 footer 없이 `!`만 쓰는 것도 허용하지만, 호환이 깨지는 내용을 footer에 명시하도록 `!`만 따로 붙이는 방법은 두지 않는다.

### body

body 칸에 입력한 내용을 그대로 쓴다. bullet을 쓸지, 몇 줄로 쓸지는 사용자가 정한다. 글자 수 제한도 없다. 앞뒤의 빈 줄만 지운다. 지우지 않으면 title이나 footer와의 사이에 빈 줄이 두 줄 이상 생긴다.

### footer

BREAKING CHANGE를 먼저 쓰고, 그 아래에 Co-Authored-By를 입력한 순서대로 쓴다.

- BREAKING CHANGE: `BREAKING CHANGE: <내용>`
- Co-Authored-By: `Co-Authored-By: <이름> <<이메일>>`

Co-Authored-By는 이름과 이메일이 모두 채워진 쌍만 조합에 넣는다. 이메일 형식은 검사하지 않는다. GitHub은 Co-Authored-By의 이메일이 GitHub 계정에 등록된 이메일(또는 `아이디@users.noreply.github.com` 주소)과 같아야 공동 작성자로 표시한다고 알고 있지만, 아직 확인하지 않았다.

## 검사

kocommit 규칙에서 내용에 관한 것은 title 길이만 검사한다. 검사는 경고만 하고 복사를 막지 않는다.

title 글자 수를 "42 / 50" 형식으로 보여 주고, 50자를 넘으면 글자 수를 경고색으로 바꾸고 미리보기에서 51번째 글자부터 경고색 배경을 깐다. 50자 위치를 고정 세로선으로 표시하지 않는다. 한글은 고정폭 글꼴에서 영문 두 칸 너비라서, 세로선이 실제 50자 위치와 맞지 않는다. 글자 수는 type, scope, `!`, 괄호, 콜론, 공백을 모두 포함한 title 전체로 센다. JavaScript의 `.length`는 UTF-16 코드 단위로 세서 이모지 하나가 2자가 될 수 있으므로, kocommit 검사 스크립트(`check.py`)가 쓰는 파이썬 `len`과 같이 코드 포인트로 세도록 `[...title].length`를 쓴다.

description이 비어 있으면 title을 만들 수 없으므로 복사 버튼을 비활성화한다.

## 복사

복사 버튼을 누르면 조합된 메시지를 클립보드에 쓰고, 버튼 자리에 "복사했어요"를 잠깐 보여 준다. `navigator.clipboard.writeText`가 실패하면 "복사하지 못했어요"를 보여 준다.

## 디자인

`git commit`을 실행하면 뜨는 에디터를 본뜬 어두운 화면이다. 미리보기는 vim에서 `COMMIT_EDITMSG`를 연 모습처럼 보이게 하고, 입력 영역도 같은 고정폭 글꼴과 주석 기호로 맞춘다.

### 배치

가운데에 최대 너비 1080px의 영역을 두고, 입력 영역과 미리보기 영역을 5:6 비율의 두 단으로 나눈다. 단 사이 간격은 48px이고, 위아래 여백은 화면 높이의 10%와 20%다. 두 단의 너비는 `minmax(0, 5fr) minmax(0, 6fr)`로 고정해서, title이 길어져도 미리보기가 입력 영역을 밀어내지 않게 한다.

미리보기는 `position: sticky`로 화면 위에서 10% 지점에 붙어 있어서, 입력 영역을 스크롤해도 계속 보인다.

화면 너비가 820px 이하면 한 단으로 바꿔 입력 영역 아래에 미리보기를 둔다. 이때 양옆 여백은 16px이고 미리보기는 따라다니지 않는다. 모바일 사용성은 범위 밖이므로 화면이 깨지지 않는 데까지만 맞춘다.

### 색

| 용도 | 색 |
|---|---|
| 배경 | `#1B1D21` |
| 입력 칸, 미리보기 배경 | `#22252A` |
| 본문 글자 | `#D7D9DC` |
| 미리보기 title 줄 | `#FFFFFF` |
| 보조 글자: 주석, placeholder, "필수", 선택하지 않은 type, 글자 수 | `#9AA0A8` |
| 옅은 글자: 줄 번호, git 안내 주석, `#`·`//` 기호 | `#6B717A` |
| 테두리, 상태 줄 배경 | `#2F333A` |
| 강조: 칸 이름, 선택한 type, 복사 버튼, 주석 안의 코드 | `#8FBF9F` |
| 경고 글자 | `#E39A7F` |
| 경고 배경 | `#4A2E27` |

보조 글자는 배경 대비 6.4:1, 옅은 글자는 3.4:1이다. 옅은 글자는 줄 번호와 기호처럼 읽지 않아도 되는 것에만 쓴다.

### 글꼴

모든 글자를 고정폭 글꼴로 쓴다. 영문은 JetBrains Mono, 한글은 Nanum Gothic Coding이 그린다. 둘 다 Google Fonts에서 불러오고, 네트워크가 없을 때를 위해 `ui-monospace`, Menlo, `monospace`를 대체 글꼴로 지정한다.

| 용도 | 크기 |
|---|---|
| 입력 칸, 미리보기 | 14px |
| type 칩 | 13px |
| 칸 이름, 주석, 상태 줄, "추가"·"삭제" | 12px |

### 입력 영역

칸 이름은 강조색으로 쓰고 앞에 옅은 글자색 `# `를 붙인다. 필수인 칸은 이름 옆에 "필수"를 보조 글자색으로 쓴다. 주석은 칸 아래에 보조 글자색으로 쓰고 앞에 옅은 글자색 `// `를 붙인다.

입력 칸은 1px 테두리에 모서리를 4px 둥글리고, 포커스가 가면 테두리를 보조 글자색으로 바꾼다. 커서는 강조색이다. body는 내용에 따라 높이가 늘어난다(`field-sizing: content`).

type은 테두리가 있는 칩 8개로 늘어놓고, 선택한 칩은 강조색으로 칠하고 글자를 배경색으로 쓴다.

"추가"와 "삭제"는 테두리 없는 글자 버튼이고, 마우스를 올리면 강조색이 된다. "+ 추가"는 Co-Authored-By 칸 이름과 같은 줄 오른쪽 끝에, "- 삭제"는 각 쌍 아래 오른쪽 끝에 둔다.

### 미리보기 영역

에디터 화면과 아래 상태 줄로 이루어진다.

에디터 화면은 줄마다 왼쪽에 줄 번호를 붙인다. 조합된 메시지 아래에 빈 줄 하나와 아래 안내 주석 두 줄을 옅은 글자색으로 보여 주고, 그 아래에 vim처럼 `~` 줄 세 개를 둔다. 안내 주석과 `~` 줄은 보여 주기만 하고 복사에는 넣지 않는다.

```
# Please enter the commit message for your changes. Lines starting
# with '#' will be ignored. 이 줄은 복사되지 않아요.
```

첫 줄과 둘째 줄 앞부분은 git이 커밋 에디터에 넣는 안내 문구이고, 끝의 "이 줄은 복사되지 않아요."만 덧붙인 문구다. description이 비어 있으면 title 자리에 옅은 글자색으로 "description"을 보여 준다.

상태 줄은 에디터 화면 바로 아래에 붙어 있다. 왼쪽에 `COMMIT_EDITMSG`와 title 글자 수("41 / 50")를, 오른쪽에 복사 버튼을 둔다. 복사 버튼 문구는 `:wq 복사`이고, 강조색 테두리 버튼이다. 마우스를 올리면 강조색으로 채운다. 비활성화되면 테두리와 글자를 옅은 글자색으로 바꾼다.

50자를 넘으면 상태 줄의 글자 수를 경고 글자색으로 바꾸고, 미리보기에서 넘친 글자에 경고 배경을 깐다.
