# Day 17 — 서비스 하나 출시하기

## 수업

오전에는 빈 폴더에서 정산 앱 하나를 기획부터 출시까지 만들며, Claude Code에서 쓰는 파일들을 언제 쓰는지 배웠다.

| 파일 | 하는 일 | 언제 쓰나 |
|---|---|---|
| `PRD.md` | 무엇을 만들고 언제 "다 됐다"고 할지 적은 기획서 | 다른 파일과 검사가 모두 이 문서를 기준으로 삼는다 |
| `CLAUDE.md` | Claude가 이 폴더에서 일할 때마다 먼저 읽는 규칙 | 모두가 지킬 규칙 |
| `.claude/agents/*.md` | 검사·리뷰를 따로 맡는 서브에이전트 | 만드는 쪽과 검사하는 쪽을 나눌 때 |
| `.claude/skills/*/SKILL.md` | 매번 같은 순서로 하는 일을 한 줄 명령으로 | 반복하는 절차 (예: `/ship`으로 만들기 → 검사 → 출시) |
| `.claude/settings.json` 훅 | 정해진 순간마다 프로그램이 무조건 실행하는 검사 | 절대 어기면 안 되는 것만 |

CLAUDE.md는 부탁이라 AI가 어길 수 있고, 훅은 프로그램이라 어길 수 없다는 차이가 기억에 남는다.

실습하며 생긴 실수는 `LESSONS.md`에 규칙으로 한 줄씩 쌓고, CLAUDE.md에서 `@LESSONS.md`로 불러왔다. 기억에 남는 것:

- 저장 버튼을 세 번 눌러 같은 지출이 3건 들어갔다. 저장한 뒤 입력 칸을 비우는 기준을 PRD에 더했다.
- AI가 고쳤다고 한 PRD에 실제로 빠진 수정이 있었다. "다듬어 줘" 뒤에는 고치기 전과 후를 비교해 확인한다.
- 시험하다 진짜 데이터를 비울 뻔했다. 시험은 환경 변수로 연습용 폴더를 지정해서 한다.

## 만든 것

### 조별: 직군별 에이전트 모음

[baby_agent](https://github.com/JJongW/baby_agent): 조원 5명(PO·개발·디자인)이 각자 만든 에이전트를 한 레포에 모았다. 레포를 받아 Claude Code로 열면 모두의 에이전트를 바로 쓸 수 있다.

내가 만든 것은 PR을 올리기 전에 브랜치의 변경이 처음 의도한 것만 담고 있는지 점검하는 `yoon-pr-intent-check`다 ([PR #12](https://github.com/JJongW/baby_agent/pull/12)). 작은 수정이 쌓여 PR이 커지면 리뷰도 되돌리기도 어려워져서 만들었다.

- 의도를 읽기 전에 diff만 보고 먼저 요약한다. 설명을 먼저 읽으면 그 관점으로만 diff를 읽게 된다.
- 의도는 한 줄 설명, 이슈 번호, 문서 경로 중 무엇으로든 받는다.
- 변경을 "의도 안 / 직접 정하기 / 분리 추천" 세 칸으로 나눈다. 의도한 코드를 고치며 같이 손댄 작은 정리는 무조건 빼라고 하면 안 쓰게 되므로 판단을 사용자에게 맡긴다.

조원의 PR 리뷰 에이전트에게 리뷰를 받고, 직접 불러 써 보며 세 번 고쳤다.

- 로컬 main이 오래되면 남의 커밋까지 의도 밖 변경으로 잡혀서, 기준을 `origin/<기본 브랜치>`로 바꿨다.
- 리포트 틀을 따르지 않고 칸이 빠지는 일이 있어 틀을 반드시 따르게 했다.
- PR에 들어가는 건 커밋뿐이라, 커밋하지 않은 변경은 점검하지 않고 목록만 알린다.
