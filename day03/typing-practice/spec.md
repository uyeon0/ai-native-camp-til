# 코드 한 줄 타자 연습: 스펙

## 개요

코드 한 줄을 보고 그대로 따라 치는 타자 연습 웹 페이지다. 화면은 VS Code 편집기를 흉내 내고, 사용자는 파일을 열어 코드를 작성하는 느낌으로 연습한다. 언어는 HTML, Python, CSS, JavaScript, Java 다섯 가지 중에서 고른다.

빌드 도구나 서버 없이 `index.html`을 브라우저로 열면 바로 동작하는 것을 목표로 한다.

## 파일 구성

`typing-practice/` 아래에 코드 파일 네 개와 글꼴 폴더를 둔다.

| 파일 | 역할 |
|---|---|
| `index.html` | 편집기 레이아웃 마크업 |
| `style.css` | VS Code 테마 색, 레이아웃, 애니메이션, `@font-face` |
| `script.js` | 입력 처리, 하이라이팅, 기록 저장, 결과 공유 |
| `snippets.js` | 언어별 문제 데이터 |
| `fonts/Jetendard-Regular.woff2` | 편집기, 터미널, 결과 카드 글꼴 |
| `fonts/OFL.txt` | Jetendard 라이선스 전문 |

`index.html`은 `snippets.js`를 먼저, `script.js`를 다음에 불러온다.

### 글꼴

글꼴은 Jetendard를 쓴다. JetBrains Mono Nerd Font Mono의 영문·기호에 Pretendard 한글을 합친 고정폭 글꼴이다. 한글 너비가 영문의 정확히 두 배라서 코드와 한글 닉네임을 한 글꼴로 그릴 수 있다.

Jetendard는 CDN이 없으므로 파일을 직접 넣는다. [banghyunmin1999/jetendard v1.0.1 릴리스](https://github.com/banghyunmin1999/jetendard/releases/tag/v1.0.1)의 `Jetendard-WebFont.zip`(약 26MB, 16가지 굵기·스타일)에서 `Jetendard-Regular.woff2`(약 1.6MB) 하나만 꺼내 `fonts/`에 두었다. 굵은 글씨가 필요한 곳은 브라우저가 Regular를 굵게 만들어 그린다.

라이선스는 SIL Open Font License 1.1이다. 글꼴 파일을 같이 배포하므로 라이선스 전문을 `fonts/OFL.txt`로 함께 둔다. zip에는 라이선스 파일이 없어서 같은 저장소 v1.0.1 태그의 `LICENSE`를 받아 두었다.

```css
@font-face {
  font-family: "Jetendard";
  src: url("fonts/Jetendard-Regular.woff2") format("woff2");
  font-display: swap;
}

:root {
  --font-code: "Jetendard", "D2Coding", Consolas, Menlo, monospace;
}
```

`index.html`을 파일로 직접 열었을 때(`file://`) Chrome 155에서 이 글꼴이 로드되는 것을 확인했다. 다른 브라우저는 확인하지 않았다. 막히면 위 순서대로 대체 글꼴로 그려진다.

### 외부 리소스

아이콘만 CDN에서 불러온다. 그 밖의 라이브러리는 쓰지 않는다.

| 리소스 | 용도 | 출처 |
|---|---|---|
| Codicons (`@vscode/codicons`) | 액티비티 바, 탐색기, 탭, 상태 표시줄 아이콘 | jsDelivr |

CDN을 불러오지 못하면 아이콘 자리는 빈다.

## 화면 구성

VS Code의 기본 레이아웃을 그대로 따른다.

| 영역 | 내용 |
|---|---|
| 타이틀 바 | 창 버튼 세 개(빨강, 노랑, 초록 점)와 `typing-practice — Visual Studio Code` 제목 |
| 액티비티 바 | 왼쪽 세로 아이콘 줄. 탐색기, 기록, 설정 아이콘 |
| 탐색기 | 언어별 파일 목록: `index.html`, `main.py`, `style.css`, `app.js`, `Main.java` |
| 탭 바 | 지금 연 파일의 탭. 입력 중에는 탭 이름 옆에 수정 표시 점(●)을 띄운다 |
| 편집기 | 줄 번호, 문법 하이라이팅, 목표 코드와 입력 코드 |
| 패널 | 하단 터미널. 한 줄을 끝낼 때마다 결과를 출력한다 |
| 상태 표시줄 | `Ln 1, Col 14`, 언어 이름, WPM, 정확도, 콤보 |

언어를 고르는 별도 드롭다운은 두지 않는다. 탐색기에서 파일을 클릭하면 그 언어로 바뀐다. 파일 아이콘 색은 언어별로 다르게 칠한다(HTML 주황, Python 파랑, CSS 하늘색, JavaScript 노랑, Java 빨강).

## 핵심 흐름

1. 탐색기에서 파일을 연다. 편집기에 그 언어의 코드 한 줄이 회색 고스트 텍스트로 나타난다. Copilot 자동 완성 제안처럼 보이게 한다.
2. 사용자가 타자를 치면 고스트 텍스트 위에 입력한 글자가 문법 색으로 덮인다. 틀린 글자는 빨간 밑줄(물결선)로 표시한다.
3. 첫 키 입력에서 타이머가 시작한다.
4. 목표 줄과 입력이 정확히 같아지면 그 줄을 끝낸 것으로 본다. 터미널에 결과를 출력하고 다음 줄로 넘어간다.
5. 줄은 위로 쌓인다. 한 세션은 10줄이고, 10줄을 끝내면 세션 결과 화면을 띄운다. 시간 제한은 없다.

### 입력 처리

화면에 보이지 않는 `<input>`이 키 입력을 받고, 편집기 영역은 그 값을 그려서 보여 준다. 편집기를 클릭하면 이 `<input>`에 포커스를 준다.

- Backspace로 지울 수 있다.
- Tab 키는 포커스 이동 대신 공백으로 처리한다. 들여쓰기가 있는 문제는 줄 앞 공백을 미리 채워 두고 사용자는 코드 부분만 친다.
- 문제는 ASCII만 쓴다. 한글 IME가 켜진 상태에서 입력이 들어오면 상태 표시줄에 "한/영 키를 확인하세요"를 띄운다.

### 지표 계산

| 지표 | 계산 |
|---|---|
| WPM | (맞게 친 글자 수 ÷ 5) ÷ 경과 분 |
| 정확도 | 맞게 친 키 ÷ 전체 키 입력 × 100 |
| 콤보 | 틀리지 않고 연속으로 맞게 친 글자 수. 틀리면 0으로 돌아간다 |

## 문제 데이터

언어마다 한 줄 코드를 20개씩 둔다. 각 문제는 아래 형태로 저장한다.

```js
{ lang: "python", code: "squares = [x ** 2 for x in range(10)]", level: 1 }
```

`level`은 1(짧고 기호가 적음)부터 3(길고 괄호, 따옴표, 연산자가 많음)까지 둔다. 세션 앞쪽은 낮은 레벨, 뒤쪽은 높은 레벨이 나오게 섞는다. 한 세션 안에서는 같은 문제를 두 번 내지 않는다.

언어별 예시:

| 언어 | 예시 |
|---|---|
| HTML | `<a href="/docs" class="nav-link">Docs</a>` |
| Python | `print(f"Hello, {name}!")` |
| CSS | `display: grid; grid-template-columns: repeat(3, 1fr);` |
| JavaScript | `const total = items.reduce((sum, x) => sum + x, 0);` |
| Java | `System.out.println("Hello, World!");` |

## 문법 하이라이팅

외부 라이브러리 없이 언어별 정규식 토크나이저를 직접 만든다. 토큰 종류는 키워드, 문자열, 숫자, 주석, 태그, 속성, 함수 이름, 기호 정도로 제한한다. 색은 VS Code Dark+ 테마 값을 쓴다.

## 재미 요소

1순위와 2순위를 구현했다. 3순위는 넣지 않았다.

### 1순위: 기본 경험을 살리는 요소

#### 터미널 출력

줄을 끝내면 실제로 코드를 실행한 것처럼 출력한다. Python이면 `$ python main.py`, Java면 `$ javac Main.java && java Main` 뒤에 `✓ Line 3 passed (62 WPM, 98%)`를 찍는다. 오타가 많았던 줄은 `⚠ 2 warnings` 같은 경고 색으로 출력한다.

#### 문제 패널

터미널 옆 "문제" 탭에 이번 세션의 오타를 VS Code 진단 형식(`main.py [Ln 1, Col 12] Expected ')' but got ']'`)으로 쌓는다. 세션이 끝나면 자주 틀린 문자를 이 목록으로 볼 수 있다.

#### 알림 토스트

업적을 달성하면 VS Code 오른쪽 아래 알림처럼 토스트를 띄운다. 예: "Extension 'Speed Typer' 설치 완료: 처음으로 60 WPM 달성".

### 2순위: 몰입감을 높이는 요소

#### 파워 모드

콤보가 일정 수(예: 20, 50, 100)를 넘으면 단계별로 효과를 켠다. 커서 위치에서 글자 색 파티클이 튀고, 50 콤보부터 편집기가 살짝 흔들린다. VS Code 확장 "Power Mode"에서 가져온 아이디어다. 설정에서 끌 수 있게 한다.

#### 직급 시스템

누적 기록에 따라 상태 표시줄에 직급을 표시한다: `Intern → Junior → Mid → Senior → Staff → 10x Engineer`. 직급 기준은 최고 WPM과 정확도를 함께 본다.

#### 테마 전환

설정 아이콘에서 Dark+, Light+, Monokai, GitHub Dark 같은 테마를 고른다. CSS 변수만 바꾸면 되므로 구현 비용이 낮다.

### 3순위: 여유가 있으면 넣을 요소

#### 버그 사냥 모드

목표 줄에 일부러 버그(빠진 세미콜론, 짝이 안 맞는 괄호)를 하나 넣고, 사용자가 고친 코드를 치게 한다. 정답 판정 로직이 달라지므로 별도 모드로 둔다.

#### 마감 모드

화면 위에 "배포까지 60초" 카운트다운을 띄우고 제한 시간 안에 최대한 많은 줄을 끝낸다. 시간이 끝나면 터미널에 `Deploy succeeded` 또는 `Deploy failed`를 출력한다. 기본 세션에는 시간 제한이 없으므로 넣는다면 별도 모드로 둔다.

#### 키 소리

기계식 키보드 소리를 Web Audio API로 낸다. 기본값은 꺼짐이다.

## 기록 저장

`localStorage`에 언어별 최고 WPM, 최고 정확도, 누적 세션 수, 달성한 업적, 고른 테마를 저장한다. 액티비티 바의 기록 아이콘을 누르면 사이드바에 언어별 기록을 보여 준다. `localStorage`에 접근할 수 없는 환경에서는 저장 없이 동작한다.

## 결과 공유

세션 결과 화면에서 결과를 공유할 수 있다. 서버가 없으므로 공유는 결과 카드 이미지와 텍스트를 만들어 사용자에게 넘기는 데까지만 한다.

### 닉네임

결과 화면에 닉네임 입력칸을 둔다.

- 1자 이상 16자 이하로 받는다. 비워 두거나 공백만 넣으면 `익명의 개발자`로 표시한다.- 입력한 닉네임은 `localStorage`에 저장하고 다음 결과 화면에 미리 채운다.
- 닉네임은 화면과 카드에 텍스트로만 넣는다. `innerHTML`에 넣지 않는다.

### 결과 카드

결과를 코드 파일처럼 보이는 카드로 만든다. 카드는 편집기와 같은 테마 색과 문법 하이라이팅을 쓴다.

```js
// result.js : typing-practice
const result = {
  nickname: "yoouyeon",
  lang: "python",
  wpm: 62,
  accuracy: 98.4,
  maxCombo: 87,
  date: "2026-10-16",
};
```

카드는 `<canvas>`에 그려서 PNG로 만든다. Jetendard가 로드된 뒤에 그려야 글꼴이 맞으므로 `document.fonts.ready`를 기다린 다음 그린다.

### 공유 버튼

| 버튼 | 동작 |
|---|---|
| 이미지 저장 | 카드 PNG를 `typing-<닉네임>-<언어>.png` 이름으로 내려받는다 |
| 이미지 복사 | `navigator.clipboard.write`로 카드 PNG를 클립보드에 넣는다 |
| 텍스트 복사 | 한 줄 요약을 클립보드에 넣는다. 예: `⌨️ yoouyeon · Python · 62 WPM · 98.4% · 최대 콤보 87` |

`index.html`을 파일로 직접 열었을 때(`file://`) 이미지 복사가 동작하는지는 확인하지 않았다. 브라우저가 막으면 이미지 복사 버튼을 숨기고 이미지 저장만 남긴다.

## 범위 밖

- 서버, 로그인, 다른 사용자와의 순위 비교. 공유한 결과가 진짜인지 검증하지 않는다.
- 결과를 URL로 공유하는 기능. 페이지가 어딘가에 배포되어 있어야 의미가 있다.
- 여러 줄 코드 블록 연습
- 모바일 소프트 키보드 최적화. 레이아웃은 좁은 화면에서도 깨지지 않게 하지만 연습 자체는 데스크톱 키보드를 기준으로 한다.
