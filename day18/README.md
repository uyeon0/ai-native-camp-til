# Day 18 — 크롤링과 수집 결정

## 수업

웹에서 데이터를 모을 때 어떤 방법으로, 어디까지 모아도 되는지 정하는 법을 배웠다. 연습 사이트에서 HTML 파싱, 동적 페이지, 숨은 API 수집을 해 보고, 퀴즈로 법적 판단과 요청 예절을 짚었다. 퀴즈에서 틀리거나 헷갈린 것은 [크롤링 퀴즈 메모](crawling-notes.md)에 정리했다.

- robots.txt는 막는 장치가 아니다. 어겨도 바로 불법은 아니지만, 거부 의사를 알고 넘었다는 증거가 된다.
- robots.txt와 약관이 다르면 더 엄격한 쪽을 따른다.
- 429는 서버 과부하가 아니라 내가 한도를 넘었다는 뜻이다. 429·403은 사이트의 의사 표시라 자동으로 재시도하지 않는다.
- 개인정보는 나중에 지우는 게 아니라 처음부터 모으지 않는다. 커밋한 CSV와 캐시에 그대로 남는다.
- 수집 방법은 공식 API > 숨은 JSON > 페이지에 박힌 데이터 > DOM 순으로 안정적이다. 공식 API도 깨지지만 미리 알려 준다.
- 할인율은 무엇과 비교했느냐에 따라 달라진다. 조건부 가격, 부풀린 정가, 다른 상품끼리 비교한 값은 지우지 말고 표시한다.

## 만든 것

### 조별: 할인 레이더

[baby_agent](https://github.com/JJongW/baby_agent)에서 조원마다 다른 분야의 할인 데이터를 모으고, 하나의 [할인 레이더 사이트](https://jjongw-baby-agent-discount-radarapp-iaxr02.streamlit.app/)로 합쳤다. 내 몫은 Steam 세일 게임 데이터다 ([PR #27](https://github.com/JJongW/baby_agent/pull/27)).

- 2026-11-06에 세일 중인 게임 414개의 가격, 할인율, 리뷰, 한국어 지원, 운영체제를 한 번 모았다.
- 403·429·리다이렉트는 0번이었고, 요청 사이는 최소 1.65초를 두었다.

### 수집처 정하기

후보 세 곳을 robots.txt, 약관, API 문서 원문으로 비교했다.

| 후보 | 결과 | 이유 |
|---|---|---|
| IsThereAnyDeal API | 탈락 | 공식 API라 데이터가 가장 좋았지만, 약관에 "경쟁 앱 금지"가 있다. 공개 레포에 배포하는 게임 할인 앱은 그 서비스와 같은 영역이다. 발급받은 키도 지웠다 |
| SteamDB | 탈락 | 약관에서 크롤링을 명시적으로 금지한다 |
| Steam 스토어 | 선택 | robots.txt가 쓰려는 경로를 막지 않는다. 약관의 "봇 금지" 조항은 계정을 쓰는 부정행위를 예로 들고 있어 스토어 공개 데이터까지 해당하지 않는다고 판단했다. 대신 요청이 오면 바로 내리기로 했다 |

처음에는 필요한 데이터를 딱 제공해주는 API라서 IsThereAnyDeal을 1순위로 뒀는데, 약관을 끝까지 읽고 나서야 우리 아이디어가 그 회사의 서비스라는 걸 알았다.

정렬도 실제로 확인하고 골랐다. 최신 출시순은 첫 50개 중 49개가 리뷰 0개였다. "평가순(`Reviews_DESC`)"은 리뷰 많은 순이 아니라 긍정 비율이 높은 순이었다. 그래서 평가순 250개와 관련도순 250개를 합쳤다.

## AI와 일한 방식

- **수집 전에 검사 에이전트를 거쳤다.** 1차 검사에서 약관 해석이 "확인 필요"로, 커뮤니티에서 도는 요청 한도 수치가 "출처 없음"으로 걸렸다. 내 판단과 근거를 문서에 적은 뒤 2차에서 통과했다.
- **약관 판단은 내가 했다.** AI는 원문을 찾아 정리했고, 위험을 감수할지는 내가 정해 이름과 날짜를 남겼다.
- **기획은 조원의 PRD 리뷰 에이전트로 점검했다.** 화면 부분과 추천 기준은 데이터 문서에서 빼고, 화면을 만드는 쪽으로 넘겼다.
