# Day 21 — Flask 폼·DB·배포 개념과 팀 조명 브랜드 사이트

## 수업

### 상태를 바꾸는 요청은 POST로 받는다

- GET은 값을 URL 쿼리스트링에 담고(`request.args`), POST는 요청 본문에 담는다(`request.form`).
- 라우트는 기본으로 GET만 받는다. `methods=["GET", "POST"]`를 적지 않고 POST를 보내면 405가 난다.
- 삭제도 POST로 받는다. GET 링크로 삭제하면 브라우저의 미리 불러오기나 크롤러가 링크를 열기만 해도 데이터가 지워진다.

### SQLite에서 놓치기 쉬운 것

- `commit()`을 하지 않으면 INSERT가 파일에 반영되지 않는다. `with con:`을 쓰면 성공하면 commit, 예외가 나면 rollback을 한다. 연결을 닫아 주지는 않는다.
- 외래 키 제약은 기본으로 꺼져 있다. 연결할 때마다 `PRAGMA foreign_keys = ON`을 실행해야 `ON DELETE CASCADE`가 동작한다.
- 타입이 느슨해서 `INTEGER` 열에도 문자열이 그대로 들어간다. 타입 검사는 앱에서 해야 한다.
- 값은 `?` 자리표시자로 넘긴다. 문자열을 이어 붙이면 입력값이 SQL로 해석된다. 테이블 이름과 열 이름은 `?`로 바인딩할 수 없으므로 허용 목록에서 골라 쓴다.
- `sqlite3` CLI에서 `.tables`, `.schema` 같은 점 명령은 셸 명령이라 SQL이 아니다. 그래서 코드에서 `con.execute(".tables")`로는 쓸 수 없다.

### 검증은 서버에서 한다

- HTML의 `required`, `maxlength`는 개발자 도구나 curl로 쉽게 우회된다.
- 서버에서 빈 값(`strip()` 후), 타입, 범위 경계값, 길이, 허용 목록을 검사한다. 실패하면 저장하지 않고 400을 돌려준다. 이때 입력값과 칸별 에러를 함께 다시 보여 준다.
- Jinja의 `{{ }}`는 HTML을 자동으로 이스케이프한다. `|safe`를 쓰거나 파이썬에서 HTML 문자열을 조립하면 이 보호가 사라진다.

### PRG와 세션

- POST 응답으로 바로 HTML을 돌려주면 새로고침할 때 같은 POST가 다시 가서 데이터가 중복 저장된다. 저장에 성공하면 redirect(302)로 GET 화면으로 보낸다. 검증에 실패하면 redirect하지 않고 400과 함께 폼을 그린다.
- Flask의 기본 `session`은 브라우저 쿠키에 저장된다. 내용은 암호화되지 않고 서명만 된다. 사용자가 읽을 수는 있지만 고칠 수는 없다.
- 서명 키인 `SECRET_KEY`는 `.env`로 분리하고 `.gitignore`에 넣는다. 배포 환경에서는 대시보드의 환경 변수에 넣는다.

### Render 무료 배포의 한계

- 요청이 한동안 없으면 서버가 잠들어서 다음 첫 요청이 수십 초 걸린다.
- 디스크가 임시라서 재배포하면 SQLite 파일이 초기화될 수 있다. 데이터를 계속 쌓으려면 외부 DB가 필요하다.
- 운영 서버는 `flask run`이 아니라 `gunicorn` 같은 WSGI 서버로 띄운다.

### 켜기·끄기는 사진 두 장의 opacity로 만든다

- 같은 구도의 켜짐·꺼짐 사진을 겹치고 위 사진의 `opacity`만 0↔1로 전환한다. 레이아웃이 바뀌지 않아 전환이 매끄럽다.
- 토글 버튼에는 `aria-pressed`를 단다. `prefers-reduced-motion: reduce`이면 `transition: none`으로 전환 없이 바로 바꾼다.

### sticky 띠는 배경을 전체 폭으로 깐다

- 본문 폭 컨테이너에 배경을 칠하면 스크롤할 때 양옆으로 아래 콘텐츠가 비친다.
- 바깥은 전체 폭 띠(배경·blur·아래 선), 안쪽은 본문 폭 `.wrap`으로 나눈다. 공통 헤더와 같은 구조다.

### 공통 토큰은 머지된 뒤에 쓴다

- 정의되지 않은 CSS 변수는 오류 없이 무시되어 스타일이 조용히 깨진다.
- 그래서 공통 토큰 PR이 머지된 뒤 토큰 적용을 별도 PR(#51)로 올렸다.
- 확정 전 디자인 값(초안의 밤 색으로 만든 다크모드)을 먼저 썼다가 규칙이 바뀌어 되돌린 일도 있었다.

### 남은 일

- 공통 카드 함수가 사진 없는 제품을 자리표시로 그리는 처리 때문에 홈 대표 제품 사진이 나오지 않는다. 홈 쪽 임시 처리만 있고 공통 함수는 아직 고치지 않았다.

## AI와 일한 방식

- 레퍼런스는 Refero, Mobbin MCP로 찾아 정리했다.
- 시안은 HTML로 만들어 공유했다. 변경할 때마다 headless Chrome으로 캡처해서 확인했고 이 과정에서 레이아웃 버그를 찾았다. 375px 폭은 도구로 확인되지 않아 휴대폰에서 직접 확인했다.
- 여러 안은 저장소 밖 복사본에서 만들어 비교했다. 저장소에는 고른 안만 넣었다.
- 작업 전에 레포의 CLAUDE.md, PRD, 디자인 규칙을 먼저 읽게 했다. 수정은 내 담당 폴더로 제한했고 매번 검사 스크립트를 돌렸다.
- 다른 조원의 PR을 읽고 내 페이지에 미치는 영향을 검토했다. 예를 들어 페이지 전환 효과의 이미지 로딩 처리가 켜기·끄기의 `opacity` 전환과 부딪히지 않는지 확인했다.
- 커밋은 데이터, 출처, 페이지, 스타일 단위로 나눴다. 이슈와 PR은 초안을 확인한 뒤 올렸다.
