# Day 20 — Flask로 데이터를 웹 서비스로

## 수업

오전에는 Flask로 웹 페이지를 만들었다.

### 상태 코드는 본문이 아니라 코드로 실패를 알린다

- `return "없어요"`는 화면에 "없어요"가 떠도 상태 코드가 200이다.
- 검색엔진과 API 클라이언트는 상태 코드로 성공을 판단하므로, 없는 페이지를 정상 페이지로 받아들인다.
- 실패는 `abort(404)`나 `(본문, 404)` 튜플로 돌려준다.

```python
return render_template("404.html"), 404
```

- 결과가 0건인 목록(`/classes?category=없는거`)은 200이다. 결과가 없는 것도 정상 응답이고, 404는 요청한 리소스 자체가 없을 때 쓴다.

### 404와 400을 고르는 기준

- **경로 변수가 잘못되면 404**: 리소스를 가리키는 값이라 "그런 리소스는 없다"가 맞다.
- **쿼리스트링이 잘못되면 400**: 리소스를 어떻게 볼지 정하는 값이라 "요청이 잘못됐다"가 맞다.
- **선택 옵션은 400 대신 기본값**: `/classes?sort=xx`의 `sort`는 없어도 동작하므로 기본순으로 보여 준다. BMI의 `h`, `w`처럼 없으면 계산이 안 되는 필수 값만 400을 낸다.

같은 404라도 정해지는 위치가 다르다.

- `/movie/abc`: `<int:movie_id>` 컨버터가 거부해서 함수가 실행되지도 않는다.
- `/movie/99`: 라우트는 맞고, 함수 안에서 데이터를 못 찾아 `abort(404)`를 부른다.

400은 Flask가 내 주지 않는다. `request.args.get("h", type=float)`는 변환에 실패하면 `None`을 돌려줄 뿐이라 코드에서 직접 판단해야 한다.

### url_for는 렌더링할 때 라우트를 확인한다

- `url_for`는 렌더링하는 순간 라우트 테이블에서 함수를 찾고, 없으면 `BuildError`를 던진다.
- 처리하지 않은 예외라서 링크 하나 때문에 페이지 전체가 500이 된다.
- 상세 라우트를 만들기 전에 목록 템플릿에 `url_for('movie_detail', ...)`를 썼다가 목록 페이지가 500이 났다.
- `href="/movie/1"`로 직접 쓰면 목록은 뜨고 클릭했을 때 404가 난다. `url_for`를 쓰면 깨진 링크가 클릭 전에 드러난다.

### 템플릿은 값을 자동으로 이스케이프한다

- Flask는 문자열 응답을 `text/html`로 보낸다. 주소에 넣은 태그가 HTML로 해석되고, `<script>`를 넣으면 실행된다(XSS).
  - `/hello/<i>hi`를 문자열로 반환하면 "hi"가 기울임체로 나온다.
- Jinja는 `.html` 템플릿의 `{{ }}` 값을 이스케이프해서 `<`를 `&lt;`로 바꿔 보낸다. 템플릿으로 바꾸면 `<i>hi`가 글자 그대로 나온다.
- `|safe`와 `Markup()`은 이스케이프를 끄므로 사용자 입력에는 쓰지 않는다.

### 빈칸은 0이 아니라 None

- 판다스는 빈칸을 `NaN`으로 읽고, 그대로 템플릿에 넘기면 화면에 `nan`이 찍힌다.
- `fillna(0)`으로 채우면 세 곳이 틀려진다. `classes.csv`(정가 빈칸 4개, 평점 빈칸 5개)에서 확인했다.
  - 화면: "0원", "0점"으로 보인다.
  - 정렬: 가격 낮은 순에서 가격 문의 클래스 4개가 맨 앞에 온다.
  - 통계: 평균 판매가가 51,754원에서 48,303원으로 내려간다.
- `data.py`에서 `NaN`을 `None`으로 한 번만 바꾼다. 그러면 쓰는 쪽마다 따로 처리할 필요가 없다.
  - 템플릿: `{% if c.price is none %}가격 문의{% endif %}`
  - 정렬: `key=lambda c: (c["price"] is None, c["price"])`로 빈 값을 맨 뒤로 보낸다.
  - JSON: `jsonify`가 `None`을 `null`로 내보낸다. `NaN`을 그대로 넘기면 JSON 표준에 없는 `NaN` 리터럴이 나간다.

### 데이터 계층을 나누고, 화면과 API가 같은 함수를 쓴다

- `data.py`: CSV 읽기, 빈칸 처리, 필터, 정렬. Flask를 import하지 않아서 Flask 없이 테스트할 수 있다.
- `app.py`: 요청을 받아 `data` 함수를 부르고 응답만 만든다.
- 사람용 화면(`/classes`, `/class/<id>`)과 프로그램용 JSON(`/api/classes`, `/api/classes/<id>`, `/api/stats`)이 같은 `data` 함수를 불러서, 화면 숫자와 API 숫자가 어긋나지 않는다.
- 실패 응답은 받는 쪽에 맞춘다. 화면은 HTML 404 페이지, API는 `{"error": "not_found"}` JSON과 404를 돌려준다.
- `/api/stats`의 숫자는 앱 코드를 보지 않고 판다스로 따로 계산해서 맞춰 본다. 전체 60, 평균 판매가 51,754원, 가격 문의 4, 평균 평점 4.28, 리뷰 없음 5로 모두 같았다.

### 포트 5000이 열리지 않을 때 (macOS)

- 증상: Flask 기본 포트 5000에서 브라우저에 "사이트에 연결할 수 없음"이 뜬다. `curl http://127.0.0.1:5000`은 200이라 코드는 정상이다.
- 확인: `lsof -iTCP:5000`을 보면 macOS 제어 센터(AirPlay 수신 모드)가 `*:5000`을 쓰고 있고, Flask는 `127.0.0.1:5000`에만 떠 있다.
- 대처: `flask run --port 5001`로 옮겼다. 원인을 끝까지 확인하지는 않았다.

## 만든 것

### 한국영화 아카이브

[korean-film-archive](https://github.com/uyeon0/korean-film-archive) ([배포](https://korean-film-archive.vercel.app)): 한국 장편 극영화 7,921편을 제작 연도와 감독으로 찾아보는 Flask 서비스다. 오전에 배운 구조(데이터 계층 분리, 화면과 API, 상태 코드, 빈칸은 `None`)를 그대로 썼다.

- 처음 기획은 지금 극장에서 상영 중인 독립영화와 재개봉작이었다.
- 실시간 상영 데이터는 영화진흥위원회 KOBIS에 있지만, 약관이 데이터 저장을 금지한다.
- 저장해 쓸 수 있는 KMDb 파일데이터 「영화기본정보」로 바꾸고 아카이브로 방향을 정했다.

### 공공데이터 원본은 그대로 믿지 않는다

- **헤더와 행의 칸 수가 다르다**
  - 헤더는 25칸, 각 행은 26칸이라 13번째 칸부터 이름과 값이 한 칸씩 어긋난다.
  - "살인의 추억"처럼 내용을 아는 행 하나로 칸마다 실제 의미를 맞춘 대응표를 만들었다.
  - 같은 데이터의 CSV판은 `pd.read_csv()`로 읽으면 첫 칸이 인덱스로 빠지면서 모든 칸이 밀린다. JSON만 썼다.
- **필요한 칸이 통째로 비어 있다**
  - 관람등급 칸이 모든 행에서 비어 있어서 성인물을 등급으로 거를 수 없다.
  - 장르에 '에로'가 들어간 영화를 빼는 것으로 대신했다. 장르가 다르게 붙은 성인물은 걸러지지 않는다.
- **한 칸에 두 값이 들어 있다**
  - 영문 제목 칸이 `Our Love Story ( yeonaedam )`처럼 영문 제목과 로마자 표기를 합친 문자열이다.
  - 마지막 괄호 묶음을 기준으로 둘로 나눴다. 괄호 짝이 안 맞는 6편은 나누지 않았다.
- **값 자체가 틀렸다**
  - 1922년 미국 영화 「Remembrance」가 제작국가 '대한민국'으로 들어 있어서 범위 조건을 통과했다.
  - 사이트를 둘러보다 발견했고, 제외 ID 목록을 두어 뺐다.
  - 편수가 7,922편에서 7,921편으로 바뀌면서 문서와 테스트의 숫자도 모두 다시 맞췄다.
- **일관되지 않은 값으로 필터를 만들지 않는다**
  - '독립영화' 키워드가 붙은 영화가 28편뿐이고, 「벌새」, 「파수꾼」에는 없다.
  - 필터를 두면 "걸리지 않음 = 독립영화 아님"으로 읽혀서 틀린 정보를 준다. 필터와 배지를 넣지 않았다.

### 상태 코드 결정

- 잘못된 `decade`, `sort`, `page`는 400 대신 기본값으로 보여 준다. 모두 선택 옵션이다.
- 마지막 페이지를 넘는 `page`는 화면과 API를 다르게 한다.
  - 화면: 404. "그 페이지"라는 대상이 없다.
  - API: 200과 빈 `items`. 페이지를 넘기는 프로그램이 빈 목록을 끝으로 판단한다.
- `/api/stats`의 편수, 평균 상영시간, 개봉일 빈칸 수, 연도대별 편수는 판다스로 원본에서 따로 계산해서 맞춰 봤다.

### Vercel 파이썬 배포에서 막힌 것

워크북은 Render 배포였지만 무료 플랜은 접속이 없으면 잠들어서 Vercel로 바꿨다.

- **`uv is required but was not found in PATH`**
  - 원인: Vercel CLI의 파이썬 빌드는 의존성 설치에 `uv`를 쓰는데, Actions 러너에는 없다.
  - 해결: `astral-sh/setup-uv@v7` 단계를 Vercel 빌드 전에 넣는다.
- **`ENOENT: no such file or directory, readlink …`**
  - 원인: `vercel build`가 저장소 파일을 모두 파이썬 함수에 넣는데, `.vercelignore`가 그중 일부를 업로드에서 뺀다. Vercel 서버가 함수에 있어야 할 파일을 찾지 못한다.
  - 해결: `vercel.json`의 `functions.<파일>.excludeFiles`로 함수에서도 같은 파일을 뺀다.
- **한글 주소만 배포 환경에서 404**
  - 증상: `/director/봉준호`가 로컬에서는 200, 배포 사이트에서는 404다. 영문과 숫자뿐인 `/film/K15340`은 정상이다.
  - 원인: Vercel 파이썬 런타임이 요청 경로를 퍼센트 디코딩하지 않고 `PATH_INFO`에 넣는다. Flask가 `%EB%B4%89…`라는 이름으로 감독을 찾는다.
  - 해결: `PATH_INFO`가 인코딩된 ASCII 문자열이면 WSGI 규약대로(디코딩한 바이트를 latin-1 문자열로) 바꾸는 미들웨어를 넣었다.
  - 로컬에서 통과한 테스트는 배포 환경을 보장하지 않는다. 배포 후 주소를 다시 확인한다.

## AI와 일한 방식

- **코드는 서브 에이전트에게 맡긴다**
  - 코드 작업은 모두 서브 에이전트에게 맡기고, 대화에서는 무엇을 고칠지 정하고 결과를 확인했다.
  - 맡길 때는 하지 말 것(커밋, 배포)과 확인 방법(로컬 빌드 결과물 열어 보기, 판다스 대조)을 같이 적었다.
- **보고를 그대로 믿지 않는다**
  - 에이전트가 검산 문서의 연도대 문장을 "숫자만 고쳤다"고 보고해서, API 값을 직접 다시 대조했다.
  - 원본 파일이 예상한 위치에 없을 때는 비슷한 파일을 추측해 쓰지 않고 멈춰서 물어보게 했다.
- **문서는 역할에 맞게 나눈다**
  - 워크북 양식대로 만든 주소 설계 문서를 다시 보고, 문서마다 역할(스펙, 원본 데이터, 검산, 데이터 필드)을 나눴다.
  - 문서 목적과 상관없는 의견과 "자세한 건 어디를 본다" 같은 문장은 지웠다.
