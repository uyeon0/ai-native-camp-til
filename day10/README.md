# Day 10 — 프롬프트 패턴과 프레임워크

## 수업

AI 답이 마음에 안 들 때 상황별로 꺼내 쓰는 프롬프트 작성법을 배웠다.

| 이럴 때 | 이렇게 시킨다 |
|---|---|
| 답이 그럴듯한데 틀린 것 같다 | "이 답에서 사실 확인이 필요한 부분을 골라 줘"라고 시키고, 고른 부분은 공식 자료로 직접 확인한다 |
| 같은 긴 요청을 매번 반복한다 | "앞으로 `/요약`이라고 하면 3줄로 요약해 줘"처럼 단축어를 정해 둔다 |
| 첫 답이 대충이다 | "방금 답을 스스로 평가하고 부족한 부분만 고쳐 줘"라고 한 번 더 시킨다 |
| 긴 글이 엉성하다 | 바로 쓰게 하지 말고 목차부터 만들게 한 뒤, 목차를 하나씩 채우게 한다 |
| 내 상황과 상관없는 일반론만 나온다 | 내 상황을 설명하는 문단을 먼저 주고, 그 위에서 답하게 한다 |
| 한쪽 입장만 말한다 | "개발자, 디자이너, 사용자 입장에서 각각 말해 줘"처럼 여러 관점을 요청한다 |
| 결론을 너무 빨리 낸다 | 단계별로 생각하게 하고, 결론 전에 반대 의견부터 말하게 한다 |
| 프롬프트를 어떻게 써야 할지 모르겠다 | AI에게 프롬프트 후보를 여러 개 만들게 하고, 그중 나은 것을 고른다 |

### 프롬프트 틀

무엇을 적어야 할지 막막할 때 칸을 채우듯 쓰는 틀이다. 칸을 채우다 보면 빠뜨린 정보가 보인다. 결국은 모두 역할·목표·상황·출력 형식의 조합이라 외울 필요는 없다.

| 틀 | 채우는 칸 | 잘 맞는 일 |
|---|---|---|
| 5W1H | 누가 · 언제 · 어디서 · 무엇을 · 왜 · 어떻게 | 계획, 일정 |
| CO-STAR | 맥락 · 목표 · 스타일 · 톤 · 대상 · 응답 형식 | 제안서, 공식 문서 |
| FOCUS | 목적 · 대상 · 핵심 메시지 · 행동 유도 · 형식 | 캠페인, 처음 보내는 연락 |
| ROSES | 역할 · 목표 · 상황 · 기대 결과 · 단계 | 협상, 문제 해결 |
| RISEN | 역할 · 지시 · 단계 · 최종 목표 · 제한 | 절차 안내, 공지, 코드 |
| BAB | 이전 · 이후 · 둘을 잇는 방법 | 스토리, 성공 사례 |

예를 들어 CO-STAR로 기업 담당자에게 보낼 제안 메일을 쓰면 이렇게 된다.

```
[맥락] 원데이 클래스 플랫폼. 기업 HR 담당자에게 팀빌딩 클래스를 처음 제안한다
[목표] 30분 미팅 약속을 잡는다
[스타일] B2B 제안서, 핵심 먼저
[톤] 정중하고 자신 있게, 과장 없이
[대상] 50명 규모 IT 회사 HR 매니저
[응답 형식] 제목 1줄 + 본문 5문단 이내 + 마지막에 미팅 가능한 시간 3개
```

어떤 틀을 쓸지 모르겠으면 AI에게 내 상황에 맞는 틀을 고르게 하고, 칸을 하나씩 질문해서 채우게 하면 된다.

채팅 안에서 정한 단축어는 새 채팅을 열면 사라진다. 계속 쓸 약속은 Claude 프로젝트 지침에 넣어 둔다.
